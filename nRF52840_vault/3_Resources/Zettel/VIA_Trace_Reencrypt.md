# VIA trace — แลก CPU กับการเห็นเส้นทางเต็ม

ทุกครั้งที่ทวน ต่อท้าย payload ด้วย `|V:<relay_id>,<rssi>` โดย `rssi` คือค่าที่ node นั้น
ได้ยิน **hop ก่อนหน้า** ไม่ใช่ค่าที่ตัวเองส่ง

```
ต้นทาง 102 (hop=0):   N:102|S:45|T:28|H:65|B:3900
nRF 116 ได้ยิน -103:  N:102|S:45|T:28|H:65|B:3900|V:116,-103
STM32 104 ได้ยิน -98: N:102|S:45|T:28|H:65|B:3900|V:116,-103|V:104,-98
```

gateway ถอดได้: `102 --(-103)--> 116 --(-98)--> 104 --> GW`

## สิ่งที่ต้องเสียไป

เดิม relay ทำแค่ `memcpy(relayPkt, packet, rxLen)` แล้วเขียนทับ header 4 ไบต์ —
**ไม่แตะ payload เลย** จึงไม่ต้อง decrypt/encrypt และ CRC เดิมยังใช้ได้

พอต่อ VIA payload เปลี่ยน จึงต้อง:
1. ใช้ `decrypted` ที่ถอดไว้แล้วตอน RX
2. ต่อ `viaBuf` ท้าย
3. `xorEncrypt()` ใหม่
4. `calculateCRC16()` ใหม่
5. ค่อยเขียน header

CPU เพิ่มไม่มาก (XOR + CRC บน ~70 ไบต์) แต่เสียคุณสมบัติ "relay โดยไม่ต้องเข้าใจเนื้อหา"

airtime: +11 ไบต์ต่อทอด · ที่ MAX_HOPS=3 เพิ่มจาก 72 เป็น 123 ms (**+71%**)

เพดาน `MAX_PAYLOAD_LEN = 200` — ถ้าเต็ม ส่งต่อโดยไม่ต่อ trace ดีกว่าทิ้งข้อมูล

## คุ้มไหม — วัดแล้ว คุ้ม

จำลองเคสหนัก (200 node · 4 โซน · 1 ช่อง · 2 นาที) เทียบเปิด/ปิด VIA:

| | PDR | ช่องใช้ |
|---|---|---|
| ต่อ VIA | 66.9% | 38.2% |
| ไม่ต่อ VIA | 65.5% | 28.5% |

ปิด VIA ลดการใช้ช่องได้จริง 10 จุด แต่ **PDR ไม่ดีขึ้น** เพราะระบบไม่ได้ติดที่การชน
แต่ติดที่ topology → เก็บ VIA ไว้ได้ ใช้ทำแผนที่ topology จริงตอน commissioning ภาคสนาม

ต่างจาก header `FROM` ที่บอกแค่ hop ล่าสุด และ `N:` ที่บอกแค่ต้นทาง — VIA ให้ทั้งเส้น
ซึ่งเป็นข้อมูลที่ต้องมีถ้าจะรู้ว่า node ตัวไหนกำลังแบก traffic ของคนอื่นอยู่
